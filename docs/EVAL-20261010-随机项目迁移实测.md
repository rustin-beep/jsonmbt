# 随机真实项目迁移实测（2026-10-10）

> 性质：**未拍板笔记**（结论入仓制度——待用户裁定后并入 PLAN）。
> 问题：随机挑真实项目，看 `.json.mbt` 能不能取代其中的 JSON。
> 一句话结论：**能替代的占 64%（其中逐字节无感替换 43%），不能直接迁移的 36% 全部落在已知边界内、零未知形态；过程中实测出 2 个此前未知的真缺陷。**

---

## 1. 先说要紧的：2 个真缺陷

### D-A（数据损坏类）Map 键不反转义 → 往返值被改写

- **表现**：`jsonmbt migrate` 判 `DIFF (round-trip mismatch)`。实测样本 608 张里 4 张命中，全部是 `nestjs/nest` 的 `sample/*/jest.json`。
- **最小复现**（`tmp/gh_rand/mapbug/`）：
  - 输入 `{"m":{"a\\b":1,"c\"d":2,"e\nf":3}}`
  - `import` 产物**正确**：`m: { "a\\b": 1, "c\"d": 2, "e\nf": 3 }`
  - `build` 回来后：`a\b` → `a\\b`、`c"d` → `c\"d`、`e<换行>f` → `e\nf`（**每个转义键都被多转义一层**）
  - 即：**import 侧对，build 侧错**；影响面 = 任何走 Map 逃生门、且键里含 `\` `"` 或转义序列的 JSON（如 jest `transform` 的正则键）。
- **根因**：`src/l0.mbt:737`
  ```moonbit
  let key = match el.key {
    String(raw) => raw          // ← 取原始源码文本，未反转义
  ```
  对照同文件 `:556` 的字段值路径是对的：`Some(JTString) | None => Json::string(unescape_string(raw, loc))`。
- **建议修法**（一行）：`String(raw) => unescape_string(raw, el.key_loc)`。
  顺带收益：`l0_map` 里 `obj.contains(key)` 的重复键判定也随之改为「按解码值判」，更符合 D-11。

### D-B（拒绝类）`is_legal_label` 与 moon 词法不一致 → 合法 JSON 被误判为内部错误

- **表现**：`hashicorp/terraform` 的 `internal/configs/testdata/valid-files/locals.tf.json`（键 `"π"`）报
  `[J0002] internal: import produced an invalid .json.mbt (generator bug); failing check says: [J1001] ... unrecognized character u32: π`。
- **设计正确的一面**：**保险丝（自检）拦住了非法产物，磁盘上没有产出坏文件**——fail loud 生效。
- **根因**：`src/infer.mbt` 的 `is_legal_label` 用「码点 ≥ 0x80 一律合法」近似 moon 的标识符规则（`:39`、`:49`），
  而 moon 真实规则是 `moonbitlang/parser@` 里**硬编码的码点区间表** `lexer/regex.mbt` 的 `RE_LIDENT_START`：
  ```
  _ a-z | U+00A1–00AC | U+00AE–02AF | U+1100–11FF | U+1E00–1EFF | U+2070–209F | U+2150–218F
  | U+2E80–2EFF | U+2FF0–2FFF | U+3001–30FF | U+31C0–9FFF | U+AC00–D7FF | U+F900–FAFF
  | U+FE00–FE0F | U+FE30–FE4F | U+1F000–1FBFF | U+20000–2A6DF | U+2A700–2EBEF
  | U+2F800–2FA1F | U+30000–323AF | U+E0100–E01EF
  ```
- **实测对账**（19 个码点，预测 19/19 命中，无一例外）：
  | 接受 | 拒绝 |
  |---|---|
  | `é`(00E9) `°`(00B0) `×`(00D7) `µ`(00B5) `Ā`(0100) `ª`(00AA) `⁰`(2070) `中`(4E2D) `あ`(3042) `가`(AC00) `𠀀`(20000) `😀`(1F600) | `π`(03C0) `α`(03B1) `А`(0400) `א`(05D0) `अ`(0905) `ก`(0E01) `\u0301` `NBSP`(00A0) `　`(3000) `０`(FF10) `℘`(2118) |
  （NBSP/U+3000 被拒是因为不在区间内，不是空白判定。）
- **影响面**：键用**希腊/西里尔/希伯来/阿拉伯/泰/天城文**等字母的 JSON（i18n、科学数据——terrafrom 这个测试样本就是数学符号 `π`）。
- **建议修法**：把 `is_legal_label` 的 `>= 0x80` 判据替换为上述区间表（或按区间判定首字符/续字符），
  未命中区间的键自动落到 Map 逃生门或给出可行动诊断，而不是走到 J0002 内部错误。

## 2. 实验设计（可复现）

- **采样器**：`tmp/gh_rand/sample.py`；种子 `20261010`，从 GitHub 6 个语言桶各取 `stars>=3000` 的 top-100 池，随机抽 2 个仓。
  排除自家仓（`rustin-beep/jsonmbt`、`rustin-beep/vitro`）。**这 12 个仓此前从未参与过本仓开发**，是纯 held-out。
- **选中的 12 仓**（`tmp/gh_rand/manifest.json` 固化）：
  `nestjs/nest` · `OpenCut-app/OpenCut` · `Dogfalo/materialize` · `airbnb/javascript` · `helm/helm` · `hashicorp/terraform` · `codewhale-hq/Codewhale` · `firecracker-microvm/firecracker` · `D4Vinci/Scrapling` · `bytedance/deer-flow` · `SeleniumHQ/selenium` · `openjdk/jdk`
- **语料**：用 `gh api` tree 列表只下 `.json`（≤256KB，剔 `node_modules/`、lock 文件等噪音），每仓上限 150 张。
- **判决口径**：`jsonmbt migrate`（默认零写）三榜 + `DIFF`：
  - `BYTE-EQ`：降级产物与原 `.json` **逐字节相同** → 换格式对下游零影响（最强"取代"）
  - `VALUE-EQ`：值语义等价、排版不同 → 值消费方无感，按字节指纹锚的下游会红
  - `REJECT`：不可迁移 → 该文件须维持 JSON
  - `DIFF`：**往返值不等**（migrate 源码注释："理论不可达、出现即产品缺陷信号"）

## 4. 为什么 BYTE-EQ 只有 43%

`migrate` 同时试紧凑档与 pretty(2)档。剩下的 VALUE-EQ 里 **107/129（83%）是「多行 + 短数组内联」**——
即 prettier/人手风格：`"types": ["vitest/globals"]`。而 jsonmbt 的 pretty 档**总是把数组展开成多行**。
实测验证：对 25 张这类文件用 `--indent 4` 重出，**0 张**恢复逐字节相等（差异不在缩进宽度，在数组布局策略）。
→ **结论：只有源文件原本就是「机器生成且格式化策略与 jsonmbt 一致」（紧凑、或 Go `json.Encoder` indent=2 那种）才可能逐字节；人写/Prettier 风格通常只能做到值等价。**

## 5. 附带发现的观察项

1. **`migrate` 跳过点目录**（实测 `_probe3`）：`.hidden/x.json` 不扫，`.dot.json` 照扫。
   本次因此漏掉 42 张真实 JSON（`.github/rulesets/*.json`、`.vscode/settings.json`、`.devcontainer/devcontainer.json`…）——
   这些恰是「人写配置」的典型目标，建议明确是跳过还是纳入。
2. `nestjs/nest`（250 张）、`terraform`（416）、`Codewhale`（335）被 150 上限截断，按路径排序取前 150，**可复现但非全量**。

## 6. 回答「能否取代」

- **不能整体取代**：36% 的文件迁不过来——但**全部**落在既知三类逃生门（Map 键名 / D-5 键集漂移建模 enum / 维持 JSON）内，没有出现"未知形态"这种坏消息。
- **能取代的部分很实**：43% 逐字节无感替换（对下游零改动），21% 值等价（读值的下游无感，按字节锚的下游需重排）。
- **两个真缺陷**（尤其 D-A 的 Map 键转义）建议优先修：D-A 属**静默数据改写类**（能过 check、产物合法但值是错的），危害高于 D-B（B 至少被保险丝拦住）。
