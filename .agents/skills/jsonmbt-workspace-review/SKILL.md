## 何时用

审**未提交改动**或**最近一个提交批**。另几类同样适用：

- **人写的分析 / 判定型脚本**——走「六问清单」，见 `references/02`。
- **一篇方案主张 / 规范修订**（含 PLAN.md 的 D 系新裁定）——把可数量化的主张（计数、`文件:行号`、结构断言）逐条**拉出来实测**；MoonBit 侧语义主张**必须探针拿一手真值**（纪律 12：探针先行），单独标注哪些是"摘自旧记录而未重采"的陈旧值。
- **新加的一批锚 / 一道闸**——有牙验证 + 三层验证，见 `references/02`。

核心纪律：**先跑门禁再读码；任何"等价 / 不等价 / 漏掉 / 多报"结论必须自造用例实证；没实测的面必须诚实列为未覆盖。**

## 铁律（违反即结论不可信）

1. **五阶段一个都不能少**——尤其**阶段 4「改原代码做边界 / 突变测试」**：只读码不注入的审阅，永远无法回答"这批锚到底有没有牙"。
2. **禁止 grep 出结论**——grep 扫文件不扫调用图。"多报 / 漏报 / 不等价 / 新增 / 漏掉"类结论必须构造用例跑一遍。
3. **本仓无 oracle**（AGENTS 纪律 4）：判据 = **RFC 8259 + moon 实测行为 + PLAN §8 的 D 系裁定**。与 Vitro 的关键差异——没有可以逐行比对的参照实现，所以：
   - "与 JSON 语义等价 / 不等价"的结论必须用**探针实测**（CLI 端到端或 moon 工具链真值）拿证据；
   - **禁从 JS / JSON 侧外推 MoonBit 语义**（Int 是 32 位、`1e2` 解析错、`Double::to_string` 三分歧——全是外推翻车后探针修正的实证，见 `03`）；
   - 往返等价的唯一口径是 **D-11 规范化器 N**：`N(build(import(J))) == N(J)`——"逐字节等价"结构上不成立，别拿它当判据。
4. **判据分层**：实现与 D 系裁定（PLAN §8）冲突 = P1 发现；**J 系错误码与 rc 五值只增不改**（D-10 纪律）；发现"实现有 PLAN 没有的行为"（实现超前于规范）= 同级红旗——R10 文档/实现比纪律，纸面化与偷跑双向都禁。
5. **语料 / 锚全绿 ≠ 正确**。门禁只覆盖锚的形状；必须补边界形状探针 + 突变抽检。
6. **禁改预期值 / 门禁数字粉饰**。发现"红"先反证是不是工具链漂移假阳性：**内层 moon test 红 → 先查工具链漂移**（升级 / 缓存毒化，见 `04`）；当前**层 2 Go 黑盒尚未落地（P1.5）**——CLI 进程契约只有手验证据，审阅报告要如实标注证据等级，**手验不冒充防线**。
7. **求值分级边界**：审阅中发现改动触碰**语言面**（`.json.mbt` 能写什么变了，L0–L2 归级）——必须走 PLAN §8 分级评审，**审阅者无权拍板**，报告里单列提请裁定；工具面（build/check/diff 输出形态）可自由加。
8. **覆盖度必须自报**。没读、没跑、没探的面一律列出，**禁把"读码未见偏差"写成"已验证正确"**。
9. **诚实归因**：报"锚缺口"前必须先判该分支**是否可达**——找得到一条区分两条路径的输入才叫缺口；找不到就是等价分支或不可达分支，属读码判定，不硬报。
10. **红→绿纪律核查**（AGENTS 纪律 5）：审**修复批**必须核对"修复提交引用了先红的用例名"；找不到先红用例 = 修复流程违规，如实报，不代为粉饰。
11. **收敛速率纪律**（防"追不存在的鬼"）：
    - 同一现象连续两轮无法给出区分性证据 ⇒ 停止深挖，降级为"未覆盖"并注明"判据不足"。
    - 一个 root cause 只修一处：发现同形点多处时，先列全清单再动手。
    - 复现不稳定时如实标注，**禁把"不稳定复现"写成"必现"**。

## 步骤（五阶段，顺序敏感）

### 阶段 0 · 定位审阅对象

```bash
git log --oneline -8
git status --short -uall          # -uall 才看得见未跟踪目录里的文件
git diff --stat
git log -1 --stat <HEAD>
wc -l <新增文件...>                # 先估规模，决定读码预算
```

工作区可能有第三方的并发未提交改动——**不属于审阅对象、也不该由你回滚**；判别口径以 `git show HEAD:` 为准，报告里写明。

### 阶段 1 · 全量门禁（先跑再读码）

命令见 [`references/06-复现清单.md`](references/06-复现清单.md)。要点：

- 每个门禁**记它自报的稳定单行**（`Total tests: N, passed: N`、warning 数）当作本轮基线。
- `moon check` 的 warning 总数是**免费回归信号**（改前 / 改后比总数，增量落到 `文件:行`）。
- **样本锚连跑**（AGENTS 环境注意；三层 = JSON 输入 → 期望 `.json.mbt` → 期望降级产物，**P1.5 import 层落地前 `probe/samples/` 现为两层**：期望 `.json.mbt` + 黄金产物），改一处连跑全部——只跑其中一层 = 门禁假绿。
- **测试计数真值 = 测试运行结果**（AGENTS 纪律 3 单点归一）；文档里的引用数字与本轮实测对账，不符即是发现（文档漂移），**改文档不改预期**。
- native 构建一律 `MOON_CC=clang` 前缀（纪律 9，MSVC 构建悬崖）；exe 路径与契约抽验见 `06`。

### 阶段 2 · 逐个读代码（不可跳）

对象 = 本批**每个新增 / 改动文件**。无 oracle ⇒ 对照轴按对象三选一：

- **校验器 / 降级器 / 诊断**：逐条对 **D 系裁定**（D-7 单文档基数、D-8 三不变量、D-10 rc 通道契约、D-11 N 语义、J 码定义 `src/diag.mbt`）。每条"异常路径"问一句：该发哪个 J 码？PLAN 里找得到出处吗？
- **数值 / 字符串面**：对 **RFC 8259 + 输出直传纪律**——降级输出 = `Json::Number` repr 源文本直传，格式化面在本仓不出现（Vitro 的 `double_to_json_text` 私有不可 import，**判据细节在 `01` §4，别照 PLAN 旧表述 grep**）；控制字符输出 `\u00XX`；字符串解码族（`src/unescape.mbt`）逐转义序列过。
- **importer 面**（P1.5 后）：对 D-1（空容器）/ D-2（Int64 归一）/ D-9（输入源集合）。

通用手法（承 Vitro）：先列函数骨架再逐段读；**同族一致性**（一串同类实现里逐个数"几个用了做法 A、几个没用"——漏掉的那处就是缺陷）；声称类结论反查（注释 / CHANGELOG 写"已对齐 D-x"的，grep 注释与 PLAN 两边——**"注释自称已登记" ≠ 真登记**）。

### 阶段 3 · 探针实验（找盲区，最高产出）

手法在 [`references/01-探针与对拍.md`](references/01-探针与对拍.md)。四类：

- **3a 输入形状探针**：`.json.mbt` 对每个构造通常只锚一种形状——换数字形态（`1e2`/负零/超 Int64）/ 转义族 / 深度 / 空容器 / Map 逃生门键 / 中文键 / 重复键 / stdin 形态就出盲区。
- **3b moon 工具链真值探针**：AST 形态 / parser / `Json` repr 的行为主张一律写最小探针拿一手真值，**禁从文档或记忆外推**（纪律 12 探针先行）；结论要进 PLAN 的再提请用户登记。
- **3c CLI 端到端**：rc 五值、stderr 机器可读前缀、原子写（失败零产物 / 不覆盖旧产物）、确定性（两次 build 逐字节 diff）——直接跑 exe 取真值。
- **3d 往返对拍**：`build(import(J))` vs **N(J)**（D-11 口径），登记的不可逐字节面（整数尾数指数 / 超 Int64 / 超 17 位有效数字 / 重复键拒绝）单独核"是否落在既登记的拒绝面内"。

探针留证放 `tmp/review_YYYYMMDD/`（已 gitignore）；**探针 `.mbt` 禁放仓库根**（根目录 .mbt 同包全编译，会污染主包编译面）。

### 阶段 4 · 改原代码做突变 / 边界注入

**只读码不注入，无法回答"锚有没有牙"。** 两类：

- **(a) 突变注入**：逐个**改坏**实现点，跑 `moon test`（单包 `-p vitro/jsonmbt/src`）；`failed == 0` ⇒ 该点无锚覆盖。
  - **无锚判定必须带对照**：同时改坏 1–2 个"已知有锚"的点，否则只能说"这套测试全没牙"。
  - **审修复批做反向突变**：把修复还原成缺陷版，期望对应用例红、还原复绿，记录红的用例名；`failed == 0` ⇒ 修复写了但锚没牙。先读提交自称的锚在哪道闸，再去那道闸上注入。
  - **同族臂结构同构**：审 J 码分派 / 降级器 emitter 臂族时，把同族所有臂并排列出对比——只看 diff 上下文行容易漏"这一个臂跟邻居不一样"。
  - 同时审**修复完整性**（一处根因常有多处同形点——如某 J 码该发的分支族）与**反向回归**（改 A 顺手碰坏 B）。
- **(b) 边界值注入**：构造边界输入看实现是否与判据同形。jsonmbt 高发边界清单见 `01` §4（数字全族 / 转义全族 / 深度预算临界 / 空容器 / 文档基数临界）。

### 阶段 5 · 脚本自证（闸与被审脚本）

- 本批**新增 / 改动的每个判定型脚本 / 闸**都要过"先证会红"：注入篡改 → 期望红 → 还原复绿。
- **审"新加的锚"**：突变注入 + 三层样本锚同步性，见 `02`。
- **审"新加的闸 / 防线"三层**：① 会红且双向；② 声称堵住的盲区真堵住了吗；③ 接线。**当前本仓无 CI** ⇒ 接线一层的结论只能是"未接线（本地手验流程）"——报告如实标注；提议接 CI 属仓库变更，提请用户拍板，不自行加。层 2 Go 驱动（P1.5）落地后，exe 新鲜度门禁 / golden 逐字节管理 / 校验和计时按 Vitro 同款模式。
- 审 `tmp/` 下人写的分析脚本走「六问清单」，见 `02`。
- 缺口给**保险丝**处方：能机判的结构性缺口建议加断言，不指望人记得。

## 覆盖度声明（强制 · 诚实报告）

报告必须有一节「未深度审阅部分」，逐项点名**没做**的事，不得省略、不得用"总体没问题"糊过去：

| 对象 | 状态 | 原因（只许下列五类） | 建议下轮动作 |
|---|---|---|---|
| 例：importer 面 | 未覆盖 | **结构性不可达**：P1.5 未实装 | 随 importer 落地首审 |

原因必须**可核对**，五类：**① 结构性不可达**（未实装 / 未落地，附"缺什么才能做"）；**② 需胶水**（附估时）；**③ 本轮未触及**；**④ 低边际价值**（附"已有什么等价证据"）；**⑤ 上下文被压缩**——**只在这一种情况下才允许提上下文窗口**，并说明丢了什么。

**禁**"时间盒 / 预算用尽"这类不可核对的含糊说法。

配套：
- **三档措辞**：`已实测（给命令+数字）` > `仅读码（给文件:行）` > `未覆盖（列入上表）`。**禁把第二、三档写成第一档的口气**。
- 阶段 1 没跑的门禁、阶段 2 没读的文件、阶段 4 没注入的模块，全部进上表。
- 结论依赖"门禁没报"时，写清该门禁**能否**覆盖该面。

## 产出（默认口头报告）

**审阅汇总只出口头报告——不写审阅文档、不为审阅结论建任何需同步的制品。** 审阅成果的落点：**对话里的报告** + **改码时的代码内注释**（自证）。

> 与 Vitro 的差异：本仓暂无 reviews 制品、无 facts 机判——发现须登记进 PLAN（新 D 系裁定 / 新 J 码 / 新里程碑状态）的，**提请用户拍板**，由用户改 PLAN（状态唯一载体在 §5 里程碑表，agent 不代改）。

**报告结构**：

1. 按五阶段报"跑了什么 / 读了什么 / 探了什么 / 注入了什么"，附自报数字；
2. 发现清单（P1 / P2 / P3，每条：**现象 + 复现命令** / **根因 `文件:行` + 判据对照** / **处方** / **为何门禁没抓到**）；
3. **未深度审阅部分**（上表）；
4. **本轮演化**（改了 skill 哪几处，见下节）；
5. 好话放最后且简短。

**探针留证**：复杂探针放 `tmp/review_YYYYMMDD/`，报告给相对路径；一次性小探针用完即删并确认 `git status -uall` 零残留。

## 演化纪律（本规程会自我积累）

**每次审阅收尾，问一遍**：这轮有没有出现"下次还会遇到"的东西？

- **准入判据**（见 `05`，三条全中才写）：可跨批次复现 / 有明确判据或查法 / 对下一次有可操作价值。
- **写入映射**：新缺陷形态 → `03`；审阅手法 / 探针对拍 → `01`；锚与闸审计套路 → `02`；审阅流程特有的工具坑 → `04`；新命令 → `06`。**通用 MoonBit 语言/工具链事实**先进 `04`，是否回灌 `docs/MOONBIT_PITFALLS.md`（Vitro 快照、编号对齐）由用户拍板——跨仓同步不是演化动作。
- **禁止写入**：一次性现场快照（commit、某次数字、批文件数）、相对时间叙事、本次审阅的结论本身。
- **变更纪律**：只追加不改写；改完必须在回复里显式列出改了哪几个文件、加了什么（**静默修改视为违规**）；每次演化在 `references/07-演化日志.md` 追加一行。

## 输出风格

**先说问题、带证据、说差多少、怎么改**；好话放最后且简短。禁"总体不错，不过…"。

每条发现必须给：复现命令、与判据（RFC 8259 / D 系 / N 语义）的具体差异、真值出处；未覆盖项必须出现在报告里。
