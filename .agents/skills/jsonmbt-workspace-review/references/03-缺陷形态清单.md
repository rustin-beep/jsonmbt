# 缺陷形态清单

> **开审前扫一遍。** 本表按"形态"聚类。起步版（2026-10-07 建）：条目取自 PLAN 已实证的坑与高危面，**尚未在本仓审阅中批量验证**——每条都是"查法"，不是"已坐实的缺陷"。
>
> 用法：拿到一批代码，按本表逐类过一遍（每类给"判据 / 查法"），比从头读一遍命中率高得多。
> **新形态追加到本表**（规则见 [`05-演化机制.md`](05-演化机制.md)）。
>
> **实例写法四条**（承 Vitro，防止单点腐化）：
> 1. **禁写一次性测量值**：测试数、`PASS n / FAIL m`、批次号、文件数——随代码演进而过期，本表只增不改，过期数字没有机制修正。
> 2. **允许写"形状"而非"真值"**：对比关系、临界样本（`2147483647` / `2147483648`）、触发条件属于判据本身，可留。
> 3. 日期只保留"形态最早可考"的场合，写成 `（Y-M 立）`。
> 4. **实例优先给"可复现判据"**（一条命令 / 一段注入写法 / 一个 `文件:行`），其次才是"当时观察到什么"。

## A · 锚的问题（测试写了但没有牙）

> **共同查法**：突变注入（改坏）+ 对照注入（改坏已知有锚的点）。只有前者全绿而后者红，才叫"这一点无锚"。

### A1 · 负样本锚覆盖不全（J 码有定义、无锚）

- **判据**：`src/diag.mbt` 的 J 码在测试里找不到至少一个负样本（PLAN §6 纪律：每码至少一负样本锚）。
- **查法**：J 码清单与负样本锚逐码对账；对缺锚的码，注入"该发此码的错实现"看红不红。
- **处方**：逐码补负样本；J 码分派臂的突变注入是最低成本的体检。

### A2 · 锚只取单一数字 / 转义形状

- **判据**：降级器 / 往返锚的样本里，数字只有常规整数、转义只有 `\n` 一类常规项。
- **查法**：按 `01` §1 矩阵列形状清单对账——`1e2` / 负零 / `2147483648` / `\0` / `\xHH` / 独代理对各至少一个判别样本。
- **实例（判据来源）**：`1e2` 是解析错而 `1.0e2` 合法；负零走 ryu-pretty 有独立形态——只锚 `1` / `2.5` 的锚对这些面零判别力。

### A3 · 锚把工具链漂移行为锚死（锚错 > 锚漏）

- **判据**：行为锚（非类型层断言）的期望值来自"某版工具链的实测"，而非规范判据（RFC 8259 / D 系）。
- **查法**：moon 工具链升级后，先判红的是"锚过期"还是"真回归"——跑最小行为矩阵（R1 对冲流程），别按锚的旧预期改实现。

## B · 分叉与等价问题（实现面）

### B1 · MoonBit 语义从外推断（本仓第一高发）

- **判据**：实现或审阅结论含"应该是 / 按 JSON 的习惯"类推断——Int 位宽、字面量语法、String 语义、Map 序。
- **查法**：任何语义主张必须有探针真值背书（`01` §6）。历史实证：Int 是 32 位（外推 2⁵³ 被推翻）、`1e2` 解析错（外推"JSON 合法即合法"被推翻）、`String` 比较非字典序。
- **处方**：结论前先跑 `01` §6 探针；PLAN 已实证的直接引用，不重推。

### B2 · check 与 build 两套校验路径漂移（D-8 明文警告）

- **判据**：`check` 与 `build` 对同一输入判定不一致（一侧红一侧绿），或校验逻辑在两条路径里各有一份。
- **查法**：对校验逻辑单点注入后分别跑 `check` / `build`——只有一侧变红即命中；grep 校验函数被两条命令路径各自调用的证据。
- **处方**：check 必须复用 build 的同一条校验路径（dry-run）。

### B3 · 输出通道与 IO 面的形态漏审

- **判据**：审了"算得对不对"，没审"写出去对不对"——stderr 前缀格式、原子写、同名覆盖、CRLF / BOM / 无尾换行输入。
- **查法**：`02` §3 的 CLI 契约抽验逐项跑；原子写专验"失败零产物 + 不覆盖旧产物 + 无 tmp 残留"三态。

## D · 闸 / 文档 / 流程问题

### D1 · 规范/实现比失步（R10）

- **判据**：D 系 ✅ 终案裁定找不到对应测试锚；或实现有 PLAN 没登记的行为。
- **查法**：D-1~D-11 逐条找锚（双向：规范有实现无 = 草稿；实现有规范无 = 偷跑）。
- **处方**：缺口列清单提请用户裁决（补锚 or 登记规范）；agent 不自行改 PLAN。

### D2 · 文档数字漂移

- **判据**：文档里的测试数 / 计数与实测不符；或同一计数在两处文档各自维护。
- **查法**：本轮实测 vs 文档引用逐处对账；计数真值应单点归一（测试运行结果）。

### D3 · 声称已对齐 / 已登记而实际未对齐

- **判据**：注释 / CHANGELOG / 提交信息写"已对齐 D-x""已登记"，但 PLAN 或锚里找不到对应物。
- **查法**：声称类结论反查——grep 注释与 PLAN 两边，两边都有才算登记。
